# Grab and Escape follow-up

Recorded during the 17 November 2026 action audit; the user explicitly deferred
this workflow from that audit's current fixes.

Authority: 4e Origin PDF pp204–206 (printed pp202–204), verified by mm-rules.
Reconsult the rules agent before implementation, particularly for size exceptions.

Required work:

- Record each grab's source, effect DC, degree and participants. Escape must remove
  only that hold and its consequences, preserving unrelated Restrained/Bound.
- Improve an existing hold without a new attack; accumulate the appropriate
  degrees. A failed improvement releases the target.
- Handle grabbing without holding and the grabber's Hindered/Vulnerable consequences.
- Sustain/release a grab, including size exceptions and relevant advantages.
- Keep simultaneous holds' bundled condition provenance independent.
- Make every stage a history request that loads the roller; no roll-request window.
- Show attack judgment, both opposed modifiers/dice, hold state and exact changes
  in shared history. Use the action audit's agreed opposed-natural interpretation.
- Cover player/NPC combinations, minions, rerolls, session replay and failed delivery.

The current basic close attack, opposed hold and basic Strength-based Escape are
not a substitute for this workflow. Do not describe full Grab/Escape as verified.
